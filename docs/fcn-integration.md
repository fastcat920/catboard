# FCN 节点接入

节点协议直接选择 **FCN v1**（原 Next 单连接）或 **FCN v2**（原恢复状态选路）。不使用 VLESS 代替协议类型。

两个选项均使用 QUIC / TLS 1.3 / BBR，复用 V2node 的权限组、账号 UUID、限速、节点倍率和计量接口。不要求设备证明或私有授权目录。客户端必须更新含 FCN 的原生核心，刷新普通 FastCat 账号订阅；新版 App 可描述原生能力，但 FCN 下发不按客户端版本过滤，只沿用账号权限组规则。

填写连接地址、连接/服务端口和权限组，再到「安全性 → 编辑配置」选择证书模式。放行服务端 UDP 端口。

| 证书模式 | FCN v1/v2 | FCN v3 | 配置 |
| --- | --- | --- | --- |
| HTTP 自动申请 | 支持 | 支持 | 新节点默认模式。域名指向节点，公网 TCP 80 可达且端口可用。由 CatNode 申请及续期。 |
| DNS 自动申请 | 支持 | 支持 | 填写 DNS 服务商及可更新验证记录的 API 凭据。由 CatNode 申请及续期。 |
| 文件（已有证书） | 支持 | 支持 | 填写节点上证书链和私钥的绝对路径。原证书工具继续管理续期。 |
| 面板下发可信证书 | 支持 | | 面板提供证书链和私钥 PEM，由管理员更新。 |
| 自签证书 + 固定公钥 | 支持 | | 面板使用同一密钥自动续签，客户端核心须支持固定公钥。 |

自动申请使用 TLS 的 `server_name`，留空时使用连接域名。连接地址为 IP 时，填入用于申请的 SNI 域名。自动模式默认由 CatNode 管理文件路径。节点同步需要的证书及 DNS 凭据留在节点接口，用户订阅下发证书身份所需的公开字段。

保存后，编辑页生成 **CatNode v0.7.1** 的 native 安装指令。启用自动模式前请更新已有的 CatNode 节点。

当前已通过面板订阅契约测试、语法检查、前端类型检查和生产构建；本地没有 Composer vendor，未跑完整 Laravel/数据库验收。尚未在本轮部署线上面板或创建公网 FCN 节点。

## FCN v3

在 V2node 编辑器选择 **FCN v3**。客户端依赖系统 CA 验证，使用 HTTP 自动申请、DNS 自动申请或系统信任的已有证书。服务端需要放行 UDP 端口。

支持 FCN v3 的客户端在原有加密订阅请求中携带 `fc_fcn3=1`。面板只给用户权限组已授权的节点下发 `type: fcn-v3`，使用用户原有的账号 UUID。节点仍从原有 V2node 接口同步配置和用户，并向同一计量接口上报。

使用自建发布源时，可以通过 `FASTCAT_FCN_V3_NATIVE_BOOTSTRAP_URL` 指定支持 FCN v3 和所选证书模式的 CatNode HTTPS 引导脚本。

自签证书与固定公钥的配置、轮换和验收见 [FCN SPKI 说明](fcn-spki.md)。
