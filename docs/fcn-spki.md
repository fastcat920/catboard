# FCN 自签证书与公钥固定

FCN v1/v2 新增两种显式身份验证方式：

- **CA 证书验证**：原有默认行为，校验系统/指定 CA、证书名称和有效期。
- **自签证书 + 固定公钥**：面板生成 ECDSA P-256 私钥与含 SAN 的自签证书，通过加密账号订阅下发 `sha256/base64(SHA256(DER SubjectPublicKeyInfo))`。私钥只在管理端和已认证的节点配置接口中使用，不进入用户节点列表或订阅。

更新面板 custom 和客户端后，在 FCN 节点编辑页选择“服务器身份验证 → 自签证书 + 固定公钥”。TLS 设置中的 SNI 留空时使用节点 host；可以填写 `www.bing.com` 并生成匹配名称的自签证书，但这不代表 Bing 官方身份，也不保证更难识别。

保存后面板自动生成身份。无需手填指纹、申请 CA 证书或修改节点证书路径。CatNode v0.5.0 已支持面板下发证书，服务器二进制不需要仅为此功能升级。保持节点通讯使用可信 HTTPS。

## 验证与更新

客户端只在显式 `spki` 模式且至少有一个合法指纹时使用公钥固定。仍检查证书名称、有效期、服务器认证用途，以及 TLS 对私钥持有者的证明。只匹配叶证书 SPKI，不接受“链中某张证书匹配”；没有首次连接自动信任，也没有匹配失败后改用 CA 或跳过校验的重试。

面板根据实际证书计算指纹，不采用调用者填写的指纹。正常编辑保留密钥；节点拉取配置时，证书在到期前 30 天内使用同一密钥重新签发，SPKI 保持不变，客户端无需为了续证刷新指纹。服务端配置刷新沿用现有节点重载机制，不承诺既有连接零中断。

如需更换密钥，在 TLS 设置中勾选“保存时更换公钥”。保存后旧订阅无法重连，需要先断开 VPN、刷新订阅后再连接；当前面板不是双阶段零中断轮换。核心可显式配置最多两个可信公钥用于受控过渡，网络对端不能自行扩展此集合。

前置子节点在订阅中继承父 FCN 节点的证书身份和 SNI；权限组筛选不变。多级父节点沿有效 FCN 父链继承身份，并防止循环；不会因此额外隐藏节点。

## 兼容性

新核心 `fastCatSupportsFCN()` 返回 2。FCN 节点是否下发仅按正常账号权限组筛选，不按客户端版本或能力标记隐藏节点。旧客户端同样会收到节点，实际连接固定公钥模式需要支持该验证方式的核心；不会降级为跳过校验。已有节点不会自动切换身份验证方式。

```yaml
- name: FCN pinned
  type: fcn
  version: 2
  server: node.example
  port: 443
  sni: www.bing.com
  uuid: <account-uuid>
  udp: true
  tls-trust: spki
  server-public-key-pins:
    - sha256/<base64-of-32-byte-SPKI-hash>
```

## 验收

`php tests/fcn_pin_smoke.php`：签发、同密钥续签、公钥轮换、普通编辑保留密钥、错误密钥拒绝、配置注入拒绝和秘密字段过滤。

`php tests/fcn_subscription_smoke.php`：旧版和新版客户端均下发 FCN、固定公钥配置下发、旧授权目录不会覆盖 FCN 身份。

PHP 实际签发的 `www.bing.com` 证书已在 Go 客户端及当前小米原生测试中完成认证 QUIC 回传。两种 FCN 配置的首次连接、续签、错误公钥拒绝、双指纹显式过渡、CA 模式不接受未受信自签证书，及错误名称/过期/用途拒绝均通过。App 的 CA 与 SPKI 适配器 TCP/UDP 测试也已在小米通过。
